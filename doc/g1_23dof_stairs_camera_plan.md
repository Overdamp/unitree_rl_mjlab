# แผนเทรนขึ้นบันไดโปร่งด้วยกล้อง depth (Phase 4 ขั้น 3–6)

เขียน 11/11/2026 · ต่อจาก `g1_23dof_stairs_plan.md` · branch `phase4-stairs` · ทำใน sim ทั้งหมดจนถึงช่วง D

## ทำไมต้องใช้กล้อง

ผลวัดขั้น 2b (`doc/g1_23dof_stairs_results/step2b_stairs_blind_vx0.5.jsonl`, vx 0.5, 64 ตัวต่อกรณี):

| ขาขึ้น สำเร็จ % | 0 cm | 3 | 5 | 8 | 10 | 12 | 15 | 18 |
|---|---|---|---|---|---|---|---|---|
| P3b (พื้นเรียบ) | 94 | 12 | 0 | 0 | 0 | 0 | 0 | 0 |
| stairs_blind (fine-tune 4000 iteration) | 66 | 23 | 44 | 0 | 0 | 0 | 0 | 0 |

- policy ที่มองไม่เห็นขั้นมีเพดานราว 5 cm ที่ 8 cm ขึ้นไปผ่านได้แค่ขั้นแรก
- stairs_blind เดินช้าลงบนพื้นเรียบ (สำเร็จ 66% โดยไม่มีตัวไหนล้ม คือเดินไม่ถึงใน 14 วินาที) จึงไม่ใช้แทน P3b
- **เส้นฐานที่ policy ใหม่ต้องชนะ:** ขาขึ้น 5 cm = 44%, 8 cm ขึ้นไป = 0%

## แนวทาง

เทรนสองชั้น (teacher → student) ตามแผนเดิม:

1. **Teacher** เห็นความสูงพื้นรอบตัวโดยตรง (`height_scan`) ข้อมูลนี้หุ่นจริงไม่มี แต่ทำให้เรียนรู้ท่าขึ้นบันไดได้เร็ว และบอกได้ว่าร่างกายของ G1 23-DoF ขึ้นขั้นสูงเท่าไรได้จริง
2. **Student** เห็นเฉพาะภาพ depth จำลองของ D455 และเรียนเลียนแบบ action ของ teacher (distillation)

ทางสำรอง ถ้า distillation ไม่ได้ผล: เทรน policy ภาพ depth ด้วย PPO โดยตรง โดยให้ critic เห็น `height_scan` (asymmetric critic)

## สิ่งที่ตรวจแล้วในเครื่องนี้ (env `unitree_rl_mjlab`)

| ของที่ต้องใช้ | มีไหม | ที่อยู่ |
|---|---|---|
| ยิง ray วัดความสูงพื้น | มี | `terrain_scan` + `height_scan` ใน `velocity_env_cfg.py` (task blind ของเราลบออก) |
| depth แบบยิง ray ตามเลนส์กล้อง | มี | `mjlab.sensor.raycast_sensor.PinholeCameraPatternCfg` (mjlab 1.2.0) |
| depth แบบ render ภาพ | มี | `mjlab.sensor.camera_sensor.CameraSensorCfg(data_types=("depth",))` |
| CNN encoder | มี | `rsl_rl.models.cnn_model` + `cnn_cfg` ใน `mjlab/rl/config.py` |
| RNN (GRU/LSTM) | มี | `rsl_rl.models.rnn_model` |
| Distillation | มี | `rsl_rl.algorithms.distillation` (rsl_rl 5.0.1) |
| กล้องบนหัวใน model หุ่น | **ไม่มี** | `g1_23dof.xml` มีแค่กล้อง `tracking` ต้องเพิ่มจุดติดกล้อง |
| CNN ต่อกับ RNN ใน model เดียว | **ยังไม่รู้** | ต้องอ่านโค้ด rsl_rl (ข้อ B5) |

## ข้อจำกัดที่ยังอยู่

- แก้เฉพาะไฟล์ของ g1_23dof ห้ามแก้ `velocity_env_cfg.py`, `mdp/*`, `deploy/include/*`
- หุ่นจริงอยู่ระหว่างซ่อม ช่วง C และ D รอจนกว่าจะแจ้ง
- ค่าบันได (ลูกนอน 0.28 m, แผ่นหนา 0.04 m, จมูก 0.02 m) และตำแหน่งกล้องเป็นค่าสมมติจนกว่าจะวัดจริง
- actor ของ teacher และ student มี observation ไม่เท่ากับ P3b จึง resume จาก P3b แบบ `strict` ไม่ได้

## ช่วง A: Teacher (เห็นความสูงพื้น)

- [ ] A1 เพิ่ม task `Unitree-G1-23Dof-OpenStairs-Teacher` ใน `env_cfgs_stairs.py`: terrain เดียวกับ blind แต่ **คง** `terrain_scan` และ `height_scan` ไว้ทั้ง actor และ critic แล้วลงทะเบียนใน `__init__.py`
- [ ] A2 ตรวจว่า ray ของ `terrain_scan` ที่ตกในช่องว่างระหว่างขั้นคืนค่าอะไร (พื้นข้างล่าง) และตัดค่า (clip) ให้ teacher ไม่สับสนกับหลุมลึก
- [ ] A3 ทบทวน reward สำหรับบันได โดยทำในไฟล์ของ g1_23dof เท่านั้น:

  - โทษ `action_rate_l2` (−0.77) และ `joint_acc_l2` (−0.47) เป็นตัวถ่วงหลักในรอบ blind พิจารณาลดน้ำหนักช่วงแรก
  - เพิ่มโทษเมื่อปลายเท้าสอดใต้แผ่นขั้น หรือเมื่อเท้าเหยียบขอบแผ่น
- [ ] A4 ทดสอบสั้น: 64 envs × 3 iteration ให้รันผ่าน แล้ววัดความเร็ว (steps/s) เทียบกับ blind ที่ 15,151 steps/s บน DGX
- [ ] A5 เขียน `run_stairs_teacher_train.sh` (แบบเดียวกับ `run_stairs_blind_train.sh`, เริ่มจากศูนย์, `--agent.run-name=stairs_teacher`)
- [ ] A6 เทรนบน DGX ดู `Curriculum/terrain_levels` ถ้าไม่ขยับเกินระดับ 2 ภายใน 2000 iteration ให้หยุดแล้วกลับไปแก้ A3 (รอบ blind ค้างที่ 1.53)
- [ ] A7 วัดด้วย `eval_open_stairs.py --task ...Teacher` บันทึกเป็น `step3_teacher_vx0.5.jsonl`
- [ ] **เกณฑ์ผ่านช่วง A:** ขาขึ้นและขาลงที่ความสูงขั้นเป้าหมาย (ค่าจาก 0.1 ถ้ายังไม่วัดใช้ 15 cm) สำเร็จ ≥ 80% และแถว 0 cm สำเร็จ ≥ 85% (ไม่เดินช้าลงแบบ stairs_blind)
- [ ] ถ้า teacher ไม่ผ่านที่ความสูงเป้าหมาย: บันทึกความสูงสูงสุดที่ผ่าน นี่คือขีดจำกัดของตัวหุ่น ไม่ใช่ของกล้อง และต้องแจ้งทีมก่อนลงแรงช่วง B

## ช่วง B: Student (เห็นภาพ depth)

- [ ] B1 เพิ่มจุดติดกล้อง D455 บนหัวหุ่น ผ่าน config ของ g1_23dof (ค่าจาก 0.2)
- [ ] B2 เพิ่ม sensor depth ด้วย `RayCastSensorCfg` + `PinholeCameraPatternCfg`: มุมมองตาม D455 (ราว 87° × 58°), ภาพเล็ก (เริ่มที่ราว 64 × 48), `max_distance` 3 m
- [ ] B3 ดูภาพ depth จำลองด้วยตา 1 env ว่าเห็นขั้นบันได เห็นพื้นผ่านช่องว่าง และไม่เห็นตัวหุ่นเอง
- [ ] B4 ทำภาพจำลองให้เหมือนของจริง (เขียนเป็น observation term ในไฟล์ของ g1_23dof):
  - ตัดระยะใกล้กว่า ~0.6 m เป็นค่า "ไม่มีข้อมูล"
  - noise ตามระยะ และจุดภาพหายแบบสุ่ม โดยเฉพาะที่ขอบแผ่นบาง
  - หน่วงเวลา (latency) แบบสุ่ม และอัปเดตภาพที่ 30 Hz ขณะ policy รัน 50 Hz
  - สุ่มตำแหน่งและมุมกล้องเล็กน้อยทุก episode
- [ ] B5 เลือกวิธีให้ student "จำ" ขั้นที่อยู่ใต้เท้าซึ่งกล้องมองไม่เห็น: อ่านโค้ด rsl_rl ว่า CNN ต่อกับ RNN ได้หรือไม่ ถ้าไม่ได้ ให้ซ้อนภาพย้อนหลังหลายเฟรมเข้า CNN แทน
- [ ] B6 เพิ่ม task `Unitree-G1-23Dof-OpenStairs-Student`: actor = obs เดิม 80 ค่า + ภาพ depth (ไม่มี `height_scan`)
- [ ] B7 ตั้งค่า distillation ใน `rl_cfg.py` ของ g1_23dof (teacher = checkpoint จาก A6) และเขียน `run_stairs_student_train.sh`
- [ ] B8 ทดสอบสั้น 64 envs × 3 iteration แล้ววัดความเร็วและหน่วยความจำ GPU ก่อนเลือกจำนวน envs
- [ ] B9 เทรนบน DGX แล้ววัดด้วย eval บันทึกเป็น `step4_student_vx0.5.jsonl`
- [ ] B10 ทดสอบความทน: ปิดภาพ depth ทั้งหมด (ค่า "ไม่มีข้อมูล") หุ่นต้องหยุดหรือเดินช้า ไม่ใช่ล้ม
- [ ] **เกณฑ์ผ่านช่วง B:** ที่ความสูงเป้าหมาย student สำเร็จไม่ต่ำกว่า teacher เกิน 10 จุด และแถว 0 cm ≥ 85%

## ความเสี่ยง

| ความเสี่ยง | สัญญาณ | ทางแก้ |
|---|---|---|
| teacher ก็ขึ้นไม่ได้ (ขีดจำกัดของตัวหุ่น 23-DoF หรือ reward) | `terrain_levels` ค้างเหมือนรอบ blind | แก้ reward (A3) ลดความสูงเป้าหมาย หรือเพิ่มความลึกขั้น |
| ยิง ray ทำให้เทรนช้ามาก | steps/s ใน A4/B8 ต่ำกว่า blind หลายเท่า | ลดขนาดภาพ ลดจำนวน envs หรืออัปเดตภาพไม่ทุก step |
| student เลียนแบบไม่ได้เพราะขั้นใต้เท้าอยู่นอกภาพ | ผ่านขั้นแรกแล้วล้มขั้นถัดไป | เพิ่มความจำ (B5) หรือปรับมุมกล้องให้ก้มลง |
| ภาพจริงต่างจากภาพจำลอง (แผ่นบาง มองทะลุ แสงสะท้อน) | พบในช่วง C | เพิ่ม noise ใน B4 หรือกรองภาพจริงก่อนเข้า policy |
| เดินพื้นเรียบแย่ลง | แถว 0 cm ใน eval ต่ำกว่า 85% | คงสัดส่วน terrain เรียบ และตรวจทุกครั้งที่วัด |
